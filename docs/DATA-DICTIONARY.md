# 路侧清算数据定义

| 原件 | 字段 |
|---|---|
| survey.json | `name` 配送区、`start,end` 带偏移整分钟，最多 48 小时；`berths` 1–12 个唯一泊位字符串。可选 `handover` 承包商交接：`at` 严格落在审查窗口内的整分钟，`outgoing`、`incoming` 为两家不同承包商名称 |
| sensors.csv | `event,berth,plate,sensor,start,end`。`event` 杆侧记录编号，`sensor` 设备名，完整区间须在审查窗口内；窗外隔离以保留实际到达匹配含义 |
| bookings.csv | `reservation,berth,plate,effective,start,end,state`。`effective` 版本开始时刻，`state` 为 `ACTIVE` 或 `CANCEL` |
| payments.csv | `receipt,berth,plate,arrival,cents`，可带可选列 `payee`。`arrival` 实际到达开始分钟；`cents` 是非负人民币分整数，最多九位，零为已收到零金额的回执；`payee` 注明该笔款归属的承包商，留空表示未注明收方 |

CSV 为 UTF-8，可带 BOM、可重排列。占位窗口、检测、预约均为 `[start,end)`，时间必须带明确时区偏移并对齐分钟。对齐用 UTC，收费自然日为 UTC+08:00。票号、预约和记录编号保留前导零。结构坏行只公开起始原件行、列数和行摘要。空文件报错，仅表头为 `header_only`，无可读记录为 `no_usable_rows`。空白和 `NULL` 收款均为非法金额。单文件限 200,000 字符。

## 占位和预约

1. 车牌先做 NFKC、去空白与中间点、大写，再用站点密钥算 HMAC-SHA256。接口、留档和下载只包含车辆代号，不保存明文车牌列。密钥跟随数据库持久化。保存原件 SHA-256 可复核来源。
2. 在格式与业务字段通过后，检测按 `event` 去重。相同的取最小行号，同一编号下不同内容整组隔离。按同一车辆和泊位归并相交与相接记录。杆侧合计和并集差值反映重复检测量。
3. 同泊位同分钟检测出多车，为 `PLATE_OVERLAP`。同车同时跨泊位为 `BERTH_OVERLAP`。同一泊位分钟优先记录前者，证据保留相关停靠。争议分钟免出账，泊位容量只计一次。
4. 预约按 `(reservation,effective)` 去重。同刻不同内容标冲突。找不晚于实际到达的最近版本，预约须覆盖到达时刻且匹配泊位与代号。取消在到达之前或同刻生效会排除该预约；之后的取消不追溯。多份生效预约以起始时刻、预约编号及原始行排序取首，并保留候选。

## 计价和应实收

- 生效预约在预约窗内，每次合并后的停靠最多首免 10 个可计分钟。补扫和日切都不重置免额。争议分钟不消耗免额。
- 每车每天在本配送区累加付费分钟，前 15 分钟每分钟 20 分，随后每分钟 40 分。新停靠与换泊位沿用同日档位，午夜重置。免费或争议时长不消耗付费档位。
- 回执先按 `receipt` 去重。相同票保留最低行号，冲突票隔离；不同回执可以对同次停靠付款。通过泊位、车辆代号和到达 UTC 分钟精确关联。金额差 = 关联实收 − 应收，逐单保留正负差值；未关联实收另列。
- 应管分钟 = 空闲 + 争议 + 首免 + 基础价 + 升级价。输出金额为整数分，页面换算为人民币元。

## 承包商交接分账

- survey 未配置 `handover` 时不产生分账，历史行为与接口结构不变。配置后，每次停靠的收费分段按交接分钟 `[start,end)` 逐分钟切开：付费、首免与争议分钟都按当时承管方归属，两家分段金额之和必须等于该单原应收，两家应收合计等于窗口原单应收总额。
- `payee` 注明交接两家之一的回执，只认给该方，且累计认领不超过其应收；超出部分留作待分金额（`DIRECTED_OVERFLOW`），不得用于抵扣另一家欠款。`payee` 为第三方名称时整笔待分（`PAYEE_UNKNOWN`）。
- `payee` 留空的回执不替任何一方猜配：关联停靠的进 `UNDIRECTED`，游离回执进 `ORPHAN_FUND`，均整笔计入待分金额。
- 分账为纯函数确定性结果，归档键随输入与规则版本生成；同一批重跑复用同一留档编号与同一笔分配，不重复划款。理赔签发前校验：两家应收之和等于原单应收、逐单切分守恒、已认实收不超过各方应收、已认实收与待分金额之和等于全部有效回执金额。
